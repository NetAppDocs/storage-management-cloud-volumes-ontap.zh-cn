= 了解 Cloud Volumes ONTAP 中的 BYOL 许可
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
自带许可证 (BYOL) 是一种 Cloud Volumes ONTAP 收费模式，您直接从 NetApp 购买许可证，而不是使用云市场订阅。

BYOL 可用于标准模式和私有模式部署，但受可用性限制。您可以在 NetApp Console 的*许可和订阅*部分的*直接许可证*下管理 BYOL 许可证。每个许可证都与您的公司和特定 NetApp 支持站点凭据相关联。

* NetApp 已限制对具有有效市场订阅的标准模式部署购买、扩展和续订 BYOL 许可证。有关详细信息，请参阅 https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/whats-new.html#restricted-availability-of-byol-licensing-for-cloud-volumes-ontap["Cloud Volumes ONTAP的 BYOL 许可可用性受限"^]。
* NetApp 正在逐步淘汰基于节点的许可，转而采用基于容量的许可。基于节点的许可证仍可用于有限数量的现有部署，包括部分 USPS 客户部署以及中国境内的部署。有关详细信息，请参见 https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/concept-licensing.html#end-of-availability-of-node-based-licenses["基于节点的许可证的可用性终止"^]。




[[byol-deployment-modes]]
== BYOL 部署模式

[role="tabbed-block"]
====
.标准模式部署
--
* NetApp 倾向于使用年度或按需付费 (PAYGO) 市场订阅来计算您的使用费用，而非 BYOL。
* 标准模式部署通常使用基于容量的许可证而不是基于节点的许可证。只有数量有限的现有标准模式部署使用基于节点的许可证。


--
.私有模式部署
--
* 私有模式部署完全依赖 BYOL 许可证，因为市场订阅在私有模式下不可用。
* 对于新部署，请使用基于容量的 Essentials 软件包，而不是基于节点的许可证。某些较旧的私有模式部署使用基于节点的许可。


--
====


[[compare-byol-license-types-in-private-mode]]
=== 在私有模式下比较 BYOL 许可证类型

下表总结了私有模式下基于容量和基于节点的许可证之间的差异。

[cols="25,37,38"]
|===
| 功能 | 基于容量的许可证 | 基于节点的许可证 


| 部署支持  a| 
新的专用模式部署仅支持基于容量的许可证，特别是 Essentials 软件包。
 a| 
新的专用模式部署不支持基于节点的许可证。只有少数现有的基于节点的部署可以继续使用它们。



| 购买  a| 
从 NetApp 购买基于容量的 BYOL Essentials 软件包，并在部署期间将其分配给您的系统。
 a| 
如果您已有使用基于节点的许可证的专用模式部署，则可以通过从 NetApp 购买 Essentials 软件包将其转换为基于容量的许可。



| 容量  a| 
前 500 GiB 的已消耗容量不计入您的许可费用。随着工作负载需求的增长，您可以购买额外的套餐。
 a| 
基于节点的许可证为单个节点或 HA 对提供高达 368 TiB 的容量。要为 Cloud Volumes ONTAP 系统分配超过 368 TiB，请购买多个许可证。例如，两个许可证提供高达 736 TiB，四个许可证提供高达 1.4 PiB。



| 范围  a| 
基于容量的许可从跨 Cloud Volumes ONTAP 系统的共享容量池中提取。您可以根据存储需求的变化重新分配可用容量。
 a| 
每个基于节点的许可证适用于一个 Cloud Volumes ONTAP 系统，并为该系统提供固定的容量。



| 可转让性  a| 
每个基于容量的许可证都与一个 Console 帐户相关联。在该帐户下创建的系统可以共享许可证容量和序列号。例如，一个 5-TiB 许可证可以支持两个各具有 2.5 TiB 的系统，或一个具有 5 TiB 的系统。您可以在 Console 中查看许可证序列号，并将同一许可证分配给同一帐户下的多个系统。
 a| 
您可以通过删除现有系统并使用许可证创建新系统来转移基于节点的 BYOL 许可证。只有 _cloud-agnostic_ 序列号适用于所有云提供商。这些序列号以 _908xxxx_ 前缀开头。

|===


[[manage-and-renew-byol-licenses]]
== 管理和续订 BYOL 许可证



[[renew-a-byol-license]]
=== 续订 BYOL 许可证

请联系 NetApp 代表续签您的 BYOL 许可证。Console 将自动获取更新后的许可证并将其安装在 Cloud Volumes ONTAP 系统上。

如果 Console 无法通过安全的互联网连接访问许可证文件，请下载许可证文件并 link:task-manage-node-licenses.html["手动将其上传到 Console"]。

要管理与 Console 关联的 NetApp 支持站点凭据，请参见 https://docs.netapp.com/us-en/console-setup-admin/task-adding-nss-accounts.html["管理与 NetApp Console 关联的 NSS 凭据"^]。



[[respond-to-an-expiration-warning]]
=== 响应过期警告

Console 会在基于节点的许可证到期前 30 天以及许可证到期时再次显示警告。选择 Cloud Volumes ONTAP 系统以查看警告并续订许可证。

image:screenshot_warning.gif["屏幕截图：显示包含警告图标的Cloud Volumes ONTAP系统。该图标表示需要采取行动。"]

如果您是组织管理员或帐户管理员并已启用该选项，则 Console 会在 Cloud Volumes ONTAP 报告中包含许可证过期警告，并通过电子邮件发送给您。

如果在许可证过期之前未续订许可证，则 Cloud Volumes ONTAP 系统将关闭。在不续订许可证的情况下重新启动系统会导致系统再次关闭。
